# 6 系统测试

## 6.1 测试目的

系统测试是软件开发过程中的重要环节，其目的是通过对系统各功能模块的系统性验证，发现系统中存在的缺陷和不符合需求的问题，确保系统在正式使用前达到预期的功能和性能要求。本次测试旨在验证社区物业管理系统各模块功能是否按照需求分析和系统设计的规格正确实现，业务流程是否完整通畅，数据处理是否准确可靠，以及系统的安全性和稳定性是否满足实际使用需求。

## 6.2 测试方法

本次系统测试主要采用**黑盒测试**方法。黑盒测试又称功能测试，测试人员不关注系统内部的代码实现细节，仅从外部用户的视角出发，通过输入特定数据并观察系统输出结果是否符合预期，来验证系统功能的正确性。具体而言，根据需求分析阶段确定的功能点设计测试用例，覆盖正常业务流程（正向测试）和异常输入处理（逆向测试）两类场景，保证测试的全面性。

测试环境配置如下：

| 项目 | 配置 |
|------|------|
| 操作系统 | Windows 11 |
| 浏览器 | Google Chrome 120+ |
| 后端服务 | Spring Boot 2.7.18，端口8080 |
| 前端服务 | Vue 3 + Vite，端口3000 |
| 数据库 | MySQL 8.0，本地部署 |
| 缓存 | Redis 6.0+，本地部署 |

## 6.4 测试结果分析

本次系统测试共设计29个测试用例，覆盖了用户登录、虚拟钱包、维修工单、投诉管理、权限控制、账单管理等核心功能模块的正常业务流程和异常边界场景。测试结果如下：

| 测试模块 | 测试用例数 | 通过数 | 未通过数 | 通过率 |
|----------|-----------|--------|----------|--------|
| 用户登录 | 6 | 6 | 0 | 100% |
| 虚拟钱包 | 6 | 6 | 0 | 100% |
| 维修工单 | 6 | 6 | 0 | 100% |
| 投诉管理 | 4 | 4 | 0 | 100% |
| 权限控制 | 4 | 4 | 0 | 100% |
| 账单管理 | 3 | 3 | 0 | 100% |
| **合计** | **29** | **29** | **0** | **100%** |

测试结果表明，系统各功能模块均能按照预期需求正确运行：

1. **功能正确性**：所有核心业务功能均通过测试，业务流程完整，数据处理准确，状态流转正确。
2. **数据一致性**：虚拟钱包缴费场景中，通过事务控制验证了账单状态、钱包余额、流水记录的原子性更新，未出现数据不一致情况。
3. **安全性**：权限控制测试表明，不同角色的越权访问均被有效拦截，返回正确的401/403状态码，JWT认证机制工作正常。
4. **输入校验**：前端表单校验有效拦截了空值和非法输入，后端接口也对关键参数进行了二次校验，系统具备良好的健壮性。

综上，系统测试结果良好，系统整体功能满足需求规格说明，达到了预期的设计目标。

## 6.5 本章小结

本章对社区物业管理系统进行了系统性的功能测试。首先说明了测试目的和采用黑盒测试的测试方法，并给出了详细的测试环境配置；然后针对用户登录、虚拟钱包、维修工单、投诉管理、权限控制、账单管理等六大核心功能模块共设计了29个测试用例，分别覆盖正常流程和异常边界场景；最后对测试结果进行了汇总分析。测试结果表明，系统各模块功能均正确实现，数据一致性良好，权限控制有效，系统整体运行稳定可靠，满足设计预期目标。
